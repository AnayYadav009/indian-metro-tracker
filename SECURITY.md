# Security policy

## Reporting a vulnerability

Please do not open a public issue for a security vulnerability. Use GitHub's private vulnerability reporting for this repository if it is enabled. If private reporting is unavailable, contact the repository owner through a private GitHub channel and include:

- a concise description and impact;
- reproducible steps or a minimal proof of concept;
- affected commit, route, or file;
- any suggested mitigation.

Do not include credentials, personal data, or live exploit payloads beyond what is needed to reproduce the issue.

## Scope

The application is a static export. Reports may include client-side code, build/deployment configuration, unsafe URL handling, dependency vulnerabilities, or accidental secret exposure. Data accuracy issues belong in the data-correction issue template, not this process.

## Response

Reports will be acknowledged when practical, investigated, and fixed or documented according to severity. Please allow time for a fix before public disclosure.
