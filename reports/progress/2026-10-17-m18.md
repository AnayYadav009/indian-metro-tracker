## 1. Executive Summary

Milestone 18 (Route Finder) has been implemented on branch `feat/m18-route-finder` strictly following the acceptance criteria in `docs/MILESTONES-v2.md` and the user instructions:
- **Client-Side Graph Search**: Computes optimal transit paths in memory from compiled operational datasets with zero server calls, zero data logging, and zero dependencies added.
- **Topological & Geometric Station Ordering**: Orders operational stations along line segments using equirectangular geometric projection fallback (`lib/routing/station-ordering.ts`).
- **Branch & Loop Support**: Fully supports branched corridors (e.g. Delhi Blue Line at Yamuna Bank, Delhi Green Line at Ashok Park Main) and circular loops (e.g. Gurugram Rapid Metro Phase 1 loop closure at Sikanderpur).
- **Multi-Criteria Optimization**: Strictly prioritizes fewest transfers first, then fewest stops, then shortest travel time.
- **Documented Operational Estimates**: Uses documented commercial speed (32 km/h), dwell time (30s), and transfer penalty (4 min). Displays a clear disclaimer note in the UI. No fares or live timings.
- **Routable-City Guard**: Validates complete ordered stations and connected operational networks. Gracefully guards networks with 0 operational stations (Surat) or pending audit defects (Bhopal PRE-01, Gurugram PRE-02) with explanatory notices.
- **UI & Map Highlights**: Responsive, mobile-first floating Route Finder panel with origin/destination search, autocomplete, swap button ("⇄"), step-by-step itinerary, URL parameter deep-linking (`?from=&to=&city=`), sliced route geometry polyline highlight on MapLibre, and origin/destination markers.
- **Zero Data Mutations**: No changes were made to `data/*.json`, `data/*.geojson`, audit rules, or audit baselines.

## 2. Implementation Architecture

### 2.1 Core Modules (`lib/routing/`)
- [`lib/routing/types.ts`](file:///c:/Anay/Programming/Projects/indian-metro-tracker/lib/routing/types.ts): Data contracts for `RouteStation`, `RouteLeg`, `RouteTransfer`, `RouteResult`, and `CityRoutability`.
- [`lib/routing/constants.ts`](file:///c:/Anay/Programming/Projects/indian-metro-tracker/lib/routing/constants.ts): Documented constants:
  - Average commercial speed: $32\text{ km/h}$
  - Station dwell time: $0.5\text{ min}$ ($30\text{ seconds}$)
  - Transfer walking penalty: $4.0\text{ min}$
  - Mandatory disclaimer text: `"Travel times are rough estimates based on a 32 km/h average speed and 4-minute transfers. Real-world schedules and train frequencies vary."`
- [`lib/routing/station-ordering.ts`](file:///c:/Anay/Programming/Projects/indian-metro-tracker/lib/routing/station-ordering.ts): Extracts sequential operational station order per segment using geometric projection parameter $P = \text{segmentIndex} + t$. Detects closed loops ($\Delta d < 80\text{ m}$) to connect terminal endpoints.
- [`lib/routing/city-guard.ts`](file:///c:/Anay/Programming/Projects/indian-metro-tracker/lib/routing/city-guard.ts): Validates network routability, returning `{ isRoutable: false, reason }` for Surat (0 operational stations), Bhopal (PRE-01 length variance), and Gurugram (PRE-02 terminal loop geometry).
- [`lib/routing/graph.ts`](file:///c:/Anay/Programming/Projects/indian-metro-tracker/lib/routing/graph.ts): Builds transit graph `(stationId::lineId)` with track edges, intra-station transfers, and inter-station interchange transfers (`interchange_id`). Implements multi-criteria Dijkstra using an efficient min-heap with lexicographical cost comparison `(transfers, stops, timeMinutes)`. Reconstructs sliced polyline geometry via `lineSlice()`.
