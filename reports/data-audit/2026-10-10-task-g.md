# Task G: Audit baseline review

## Result of the pipeline/audit fix

The `station-gap` rule was comparing stations sorted by `station_id`, not by
their position on route geometry. This produced false gaps between ordinary
adjacent stations. The audit now projects each station onto its nearest segment
of the same line and compares stations in segment/geometry order.

| Measure | Before fix | After fix |
|---|---:|---:|
| Total warnings | 1,219 | 726 |
| Un-baselined warnings | 757 | 264 |
| Errors | 30 | 30 |
| Station-gap warnings | 192 Delhi plus 328 other-city findings | 27 total |

No threshold was changed.

## Proposed baseline policy

The existing baseline should be extended only after the following review:

| Category | Proposed action | Reason |
|---|---|---|
| Future records without verified dates/references | Baseline individually with source-review reason, or add official references/dates | Unknown dates remain null; warnings must remain visible |
| Default/unverified station layouts | Baseline individually pending operator station-list verification | No layout facts should be invented |
| Reference count/terminal mismatches | Baseline only where the reference itself is marked unverified or incomplete | Preserve the discrepancy for later source reconciliation |
| `station-gap`, `polyline-hook`, `reference-station-missing` | Keep active; do not blanket-baseline without line-level review | These are the newly requested data-quality rules |
| Geometry endpoint/nearest-segment warnings | Fix geometry or station association first; baseline only with a documented source-backed exception | Potential real pipeline/data defects |
| Interchange/name-quality findings | Correct metadata where verified; otherwise baseline with an explicit source limitation | Avoid silently changing real-world names |

The 30 errors remain un-baselined and block a passing audit. They are
primarily station-to-segment association errors introduced or exposed by the
force rebuild:

- 18 Mumbai construction/planned station associations
- 7 Noida station/line geometry associations
- 2 Navi Mumbai findings
- 1 each in Bengaluru, Chennai, and Delhi

These should not be converted into warnings or hidden by baseline entries.
They require source-backed station association or geometry fixes before
`npm run audit:data` can exit 0.
